# SwarmShield Tactical 3D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the active 2D tactical canvas with a responsive, offline Three.js operational viewer driven entirely by existing SwarmShield simulation snapshots and events.

**Architecture:** Keep `static/app.js` as the application/controller and add `static/tactical3d.js` as a focused renderer with a small public API. The controller owns payloads, authoritative discrete time, playback, strategy, and panels; the renderer owns only the 3D scene and interpolates positions visually between real snapshots.

**Tech Stack:** Python 3.10+ standard library, vanilla JavaScript ES modules, Three.js r186 (`0.186.0`), matching OrbitControls, HTML, CSS, `unittest`, and browser automation/manual verification.

## Global Constraints

- Preserve `python -m swarmshield.webapp` and `http://127.0.0.1:8765` with no build step.
- Python is the sole simulation source of truth; JavaScript may interpolate position only.
- State, assignments, intercepts, failures, leaks, metrics, and events must use real discrete backend data.
- Preserve API payloads, scenario generation, custom JSON, dynamic-events control, strategies, panels, and tests.
- Map `(x, y, z)` to `(x, z * 3, y)` through one `VERTICAL_SCALE = 3` visualization constant.
- Vendor official Three.js r186 and the matching OrbitControls from the same tag; no CDN, npm, or runtime network dependency.
- Use one scene and renderer for both strategies; clear all strategy-derived visual state on switching.
- Reuse geometry/materials, cache meshes by ID, limit trails to 20 seconds, cap pixel ratio, and avoid permanent moving-entity labels.
- Do not change allocator or backend simulation behavior. Report any genuine allocator defect before editing it.
- Keep the existing operational visual identity and synthetic/model-boundary disclaimers.

## File map

- Create `static/tactical3d.js`: Three.js scene, indexed real trajectories, visual interpolation, entities, lines, trails, picking, cameras, resize, and disposal.
- Create `static/vendor/three.module.js`: unmodified official Three.js r186 ES module build.
- Create `static/vendor/OrbitControls.js`: unmodified official Three.js r186 control add-on.
- Create `static/vendor/LICENSE`: upstream MIT license.
- Create `static/vendor/README.md`: version, tag, source URLs, hashes, and local import-map usage.

- Modify `static/styles.css`: responsive 3D viewport, overlays, controls, labels, tooltip, and retained dashboard styling.

- Modify `README.md`: offline 3D viewer, controls, fixed dependency, and unchanged launch command.

- Do not modify `swarmshield/models.py`, `scenario.py`, `allocator.py`, or `simulator.py` unless an independently reported blocker is approved.

- [ ] **Step 3: Implement data indexes and coordinate mapping**

Add pure helpers:

```js
export function simulationToWorld(record, target = new THREE.Vector3()) {
  return target.set(record.x, record.z * VERTICAL_SCALE, record.y);
}
```

Index trajectories per strategy as ordered times plus `Map<time, Map<entityId, record>>`. Compute adjacent samples for position interpolation. Clamp interpolation at the first/last real sample.

- [ ] **Step 4: Enforce discrete state**

For every entity, obtain state, assignment, risk, committed, asset, and class exclusively from `framesByTime.get(discreteTime)`. Interpolate only the two world position vectors. If an entity lacks either adjacent positional sample, use the available real sample without extrapolation.

- [ ] **Step 6: Implement assignment lines without stale state**
